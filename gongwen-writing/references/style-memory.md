# 公文风格档案规范

## 概览

风格档案是“妙笔生花”自学习能力的持久化载体，记录用户与单位的行文偏好，使技能跨会话“越用越懂你”。

## 存放位置

- **固定私有路径**：`~/.miaobi-shenghua/公文风格档案.md`（Windows 下即 `%USERPROFILE%\.miaobi-shenghua\公文风格档案.md`）
- **不放在当前工作目录**：工作目录可能是 git 仓库或共享文件夹，档案会被提交或随项目外传
- 兼容旧档案：如果当前工作目录里已有 `公文风格档案.md`，读取并使用，同时提示用户是否迁移到私有路径

## 何时读写

- **写作前读取**：进入写作流程时，检查私有路径是否已有档案；有则读取并应用其中偏好，无则按通用公文语体写作
- **首次写入前征得同意**：档案还不存在时，先问一句“要不要把这些偏好记下来，下次直接用？”，用户同意再创建
- **交付后更新**：收到用户反馈后，将本次新观察到的偏好**增量**写入档案；无新发现则不改动
- **增量原则**：只追加或修正有变化的条目，保留历史有效偏好，不整篇覆盖
- 每次写入后简要告诉用户记了什么（一句话），用户可以要求删除

## 档案结构

档案由以下区块组成（按需填写，无内容的区块可省略）：

- **单位信息**：单位全称、常用简称、层级、行业领域
- **用户偏好**：篇幅倾向、语气倾向、详略偏好、常用过渡与结语
- **领导风格画像**：按领导分别记录句式偏好、高频词、修辞习惯、语气节奏
- **常用表述库**：本单位高频使用的规范表述、固定提法
- **反馈要点**：用户历次修改中反复出现的诉求（如“忌啰嗦”“语气要硬”）

## 条目示例（原子片段）

一条用户偏好记录的标准写法：

```
- 篇幅：倾向简洁，单篇通知控制在 400 字内（来源：2026-11 用户反馈“太啰嗦”）
```

一条领导风格画像记录的标准写法：

```
### 张厅长
- 句式：喜用短句排比，开头常以“要…要…要…”领起
- 高频词：抓手、闭环、底线思维
- 语气：部署工作偏硬朗，少用商量口吻
```

智能体应根据真实交互动态生成条目，而非复制此示例填满档案。

## 写入前的保密自检（每次必做）

写入前逐条检查待写内容，命中任一项就**不写入**该条（或改写为抽象的风格描述）：

- [ ] 含密级字样（绝密、机密、秘密、内部）或来自涉密文件
- [ ] 含具体金额、预算数、资金分配结果
- [ ] 含具体项目名称、企业名称、未公开的政策内容
- [ ] 含人事信息（任免、考核、处分）
- [ ] 含发文字号、文件全文或大段原文摘抄

档案只记“怎么写”，不记“写了什么”。例：可以记“厅长喜欢用‘过紧日子’的提法”，不能记“××项目安排××万元”。

## 冲突与边界

- 领导风格与用户个人习惯冲突时，署名公文以领导风格为准
- 偏好来源应可追溯（标注来自哪次反馈），避免凭空臆断
