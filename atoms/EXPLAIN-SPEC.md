# 原子讲透规范（atoms/explain/）

目标：把每一个原子讲到「学生看完能认出、能用、知道什么时候别用」。

## 文件
- 每个引擎一份：`atoms/explain/<engine>.md`（如 `luxun-writing.md`）。
- 原子顺序、编号、名称与 `atoms/index.json` 完全一致；不增不删不改名。
- 文件开头一段 ≤150 字的「本引擎总述」：这种文风的魂是什么、这些原子如何配合。

## 每个原子的固定结构
```
## <id> <名称>
**族**：<与 index.json 一致>　**档位**：核心 | 常用 | 签名

**一句话**：它是什么（≤40 字，说人话）。

**为什么管用**：读者读到时发生了什么（心理/节奏/信息层面），≤120 字。

**原文示范**：
> 公版作者可引原文（≤60 字，注出处）；在世/保护期作者不引原文，改写「手法复述」并标【复述】；没有可靠出处就自写示范并标【示范】。

**拆开看**：示范里这个原子落在哪几个字、怎么起作用（2–4 条）。

**用过头**：一段 ≤60 字的反例，演示 AI 腔/套路腔式的滥用，并一句话指出病在哪。

**什么时候别用**：1–2 条。

**最小练习**：一道 5 分钟能完成的题。
**自查标准**：一条能判断「做到了没有」的检查句。

**相邻原子**：同族或易混的 1–3 个原子 id，一句话说区别。
```

## 档位定义（分类策略）
- **核心**：跨文体通用、决定文章成败（如画面、节奏、收尾、视角类），学写作必须先练。
- **常用**：多数文体可用，但需看场合。
- **签名**：某位作者的标志动作，学来欣赏与理解，不建议初学者直接模仿。

## 硬规矩
- 禁止编造名家原话；拿不准就用【复述】或【示范】。
- 反例要真像 AI 会写的那种，不要稻草人。
- 不用金句腔、不用鸡汤、不写“总之”“综上”。
- 每个原子 400–700 字。
