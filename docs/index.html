风 一何为采风

周代设采诗之官，行于四方，收集民歌，以观风俗，知得失。《诗经》的「国风」，就是这样来的。

古人采风，目的不在于把歌攒起来，而在于从歌里看出一地的规律。这个仓库做的是同一件事：从真实文本里，拆出一种文体的造法。

采，是拆解，不是收藏。— 所以这里没有范文合集，也不保存语料全文
风 二一个引擎

一种文体，本质上是一套作者没说出来的操作规则。

写作课教你的「要有细节」「要克制」「要有网感」，是这些规则被总结之后的样子，不是它们运转的样子。引擎把它拆成三道，各管一段。

原子ATOMS

可复用的最小技法与组合规则。管「怎么写」。

指纹FINGERPRINT

可数的风格特征。管「像不像」，能自检、能打分。

红线RED LINES

一碰就露怯的禁区。管「不能怎么写」。

  • 只有原子 → 一本无法自检的范文集
  • 只有指纹 → 只能判卷，不能写作
  • 只有红线 → 绕回提示词模板
风 三模板与引擎
提示词模板采风引擎
给你什么成品长什么样成品怎么长出来的
能不能自检不能，只能凭感觉指纹可数、红线可查、checker 可打分
会不会生长用完即弃每次实战反哺
覆盖范围一个腔调一种文体的全部构件

模板是尸检报告，引擎是手术。

三个引擎都能反向用：给它一篇现成文章，它按原子链拆解、做红线体检，告诉你用了哪几招、哪几处露怯、怎么改。

风 五造一个引擎

引擎不是攒出来的，是造出来的。

  1. 采样选一种边界清楚的文体，收集真实、成色足的文本。
  2. 拆原子逐篇拆出最小技法，归并成可组合的操作。
  3. 立指纹把「像」变成可数的特征，能计量、能对照。
  4. 划红线写下一碰就露怯的禁区，并给出替代写法。
  5. 实战回灌用引擎写真文章，失败处反哺原子与红线。

每个引擎遵守同一份七节契约（见 SPEC.md），并通过 lint_skill.py 的十项检查才能收录。

frontmatter 完整七节齐全无语料全文examples 有完整产出
风 六安装与使用

SKILL.md + frontmatter 是通用格式。以 OpenClaw 为例：

git clone https://github.com/Greatbeing/writing-engines.git
cp -r writing-engines/human-voice-writing \
      writing-engines/guanfang-writing \
      writing-engines/feature-writing \
      ~/.openclaw/workspace/skills/

Claude Code 或其它支持 SKILL.md 的宿主：把引擎目录放进对应的 skills 路径即可。目录自包含，无代码依赖。

一句话需求进，一篇文章出。写完可以自检：

# 按引擎给一篇文章打 AI 味分
python tools/ai-flavor-checker.py article.md --engine human-voice-writing
