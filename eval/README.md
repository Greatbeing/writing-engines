# eval · 评测

> 这个目录是整个仓库的地基。
> 没有它，「可安装、可执行、可评测」里的第三个词是空头支票。

## 它回答一个问题

**用了引擎，文章比不用更好吗？好多少？**

在此之前，仓库里对这个问题的所有回答都是「我觉得」。这个目录把「我觉得」
换成三个数字：

1. **胜率** —— 引擎输出被盲评者排在裸模型输出之前的比例（带置信区间）
2. **可区分度** —— 三个引擎写同一题，盲评者能不能分出它们
3. **每题最优引擎** —— 未来的「选题→选引擎」路由就靠这个

## 五条命令

```bash
# 1. 抽签：决定哪篇文章用哪个匿名标签（只跑一次，之后不要再跑）
python3 eval/score.py --make-key

# 2. 出任务书：10 题 × 4 版 = 40 份，每份含题目 + 统一素材包 + 输出要求
python3 eval/tasks.py

# 3. 生成：对每份任务书各生成一次，存成 eval/runs/<题号>--<引擎>.out.md
#    （这一步用到你的模型；纪律见 tasks.py 的提示）

# 4. 做盲评包：检测泄露 → 按分配切成 eval/blind/<评分者>/<题号>/<标签>.md
python3 eval/blind.py

# 5. 汇总：组织评分者填完 eval/rankings.csv 后
python3 eval/score.py --template > eval/rankings.csv   # 空白评分表
python3 eval/score.py --input eval/rankings.csv > eval/RESULTS.md
```

`eval/blind.py` 有一道硬闸：**模型把指令抄进正文（比如「按原子 5 的写法……」）
时会直接失败并指出文件与上下文**。这类泄露会让评分者反推版本，整轮排序作废，
而且从数据上看不出来——所以必须拦在生成阶段。

## 目录

```
eval/
├── README.md        本文件
├── DESIGN.md        实验设计：为什么这么干，什么算失败
├── prompts.json     10 个题目 + 每题统一的素材包
├── tasks.py         生成 40 份任务书
├── blind.py         泄露检测 + 盲评包切分 + 分配表
├── score.py         抽签、评分表、汇总、置信区间判读
├── key.json         题号 → 匿名标签 → 引擎（--make-key 生成，别给评分者看）
├── assign.json      每题由哪 2 位评分者评（blind.py 生成）
└── RESULTS.md       结果（现在是空的，等着被填）
```

`eval/runs/` 与 `eval/raw/` 已在 `.gitignore` 里：那是未脱敏的模型输出。

## 三条纪律

1. **评分者不知道哪篇是什么。** 交给他们的只有 `eval/blind/<自己>/` 这个目录，
   里面全是 `t01/A.md` 这样的文件。谁看到 `key.json`，这一轮作废。
2. **同一题四个版本拿到同一个素材包。** 素材包写死在 `prompts.json`。
   否则比的不是引擎，是「谁编的素材更具体」。
3. **结果哪怕是负的也要发。** 如果盲评显示引擎没有优势，那是这个仓库最有价值
   的一条信息——它说明该改引擎，而不是该继续加引擎。
