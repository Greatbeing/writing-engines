# explain-pilot-r2 · 讲透全文比只知道手法名多出多少（第二轮试点）

> 日期：2026-11-26。样本：3 个原子 × 3 道新题 × A/B/C 三组 = 27 篇。偏好评分每题 2 人、共 18 次排序；另有 1 位手法判定者给 27 篇打手法分。
> 所有数字都由 `pilot.py score` 从 `ratings.csv`、`judge.csv` 经 `key.json` 解盲后算出（见 results.md、results.json），没有手算。
> 这一轮只能说方向，不能说“显著优于”。局限见第五节。

三组条件：A 只给原稿和“改得更好”；C 再加手法名和讲透里的“一句话”定义；B 再加该原子讲透一节的全文（由脚本从 atoms/explain/ 逐字切出，不删节，见 prompts/）。

## 一、结论

1. **B 对 C（讲透全文比只知道手法名多出的部分）：12/18，67%，Wilson 区间 43.7%–83.7%，判为“不确定”。** 区间跨过了 50%，所以不能说讲透全文整体更好。三个原子的结果差别很大：
   - versailles.10 淡收：B 对 C **6/6**，区间 61.0%–100%，判为通过。
   - luxun.1 小处切入：4/6，不确定。
   - luxun.9 冷笔白描：**2/6，B 输给了 C**，不确定。
2. **C 对 A：15/18，区间 60.8%–94.2%，判为通过。** 只给手法名加一句话，就已经拿到了大部分提升。第一轮里 B 对 A 的优势，大头来自“知道要做什么”。
3. **B 对 A：18/18，区间 82.4%–100%**，和第一轮一样。不过评分者这次不知道手法名，所以这个结果不再受“评分标准偏向 B”的影响。
4. 讲透全文的额外价值集中在**最容易用错的环节**。淡收的“用过头”一节专门点了“哈哈/开玩笑”和“叹气前先放警句”这两个坑。C 稿里 q09 还在用“跑慢一点或许更自在”这类警句，B 稿则全部避开了。冷笔白描的一句话定义（“情绪不出口，结尾最冷”）本身已经足够好用，全文没有带来额外收益。

| 原子 | B>A | B>C | C>A |
|---|---|---|---|
| luxun.1 小处切入 | 6/6（61.0–100%）通过 | 4/6（30.0–90.3%）不确定 | 6/6（61.0–100%）通过 |
| luxun.9 冷笔白描 | 6/6（61.0–100%）通过 | 2/6（9.7–70.0%）不确定 | 6/6（61.0–100%）通过 |
| versailles.10 淡收 | 6/6（61.0–100%）通过 | 6/6（61.0–100%）通过 | 3/6（18.8–81.2%）不确定 |
| **合计** | **18/18（82.4–100%）通过** | **12/18（43.7–83.7%）不确定** | **15/18（60.8–94.2%）通过** |

“B>C”指在同一次排序里 B 排在 C 前面。两位评分者有 8/9 题给出了完全相同的三篇排序。

## 三、两项专门检查（来自 checks.json 和评分理由）

### 淡收 B 稿是否仍照抄示范？**没有。**
- 3 篇 B 稿都没有出现“楼下”“唉，不说了”“扔进抽屉”“早凉了”“埃塞俄比亚”“来了。”“另外几块”这几处示范原句（demo_hits 均为空），也都没有“哈哈”“开玩笑”“凡尔赛”。
- 3 个结尾形态各不相同：q07 落在物件（京都旅馆的确认邮件，没点开），q08 落在动作（起身关纱帘，走了好一会儿才走到），q09 落在物件（奖牌挂上钉子，钉子又弯了一点）。这正好对应修订后讲透里“动作、物件、对白”三种示范，第一轮“楼下等着”那种单一模板没有再出现。
- 反倒是 **C 稿出现了模板化**：q07-C 和 q08-C 都以“长长地（呼/出）了一口气”收尾。q09-C 在叹气前先放了一句“跑慢一点，或许更自在些”，判定者点名为“叹气前先放警句”，正是讲透“用过头”第二条描述的毛病。

### 冷笔白描 B 稿是否仍成流水账？**没有。**
- 时间词数：q04-B 1 个（快六点），q05-B 2 个（凌晨四点、七点不到），q06-B 1 个。三篇都没有感叹号，也没有“令人”“深深”。
- 判定者认为 q05 里**最接近流水账的是 C 稿**：“十一点……下午三点……二十三斤”，评语是“后段时间和数字偏多”。B 稿收在“收废品的明天来，按斤称”，被评为本题最冷、最到位的结尾。
- 但冷笔白描是 B 唯一没有赢过 C 的原子。q04 的两位评分者都把 B 排在第一（结尾“系好了鞋带”）；q05、q06 则都把 C 排在第一，理由是 C 的细节更密，结尾更有分量，比如 q06-C 的“自己开了门”，B 稿相比之下“略单薄”。讲透全文让 B 写得更克制、更短（平均 227 字，C 平均 258 字），却没有带来更好的读感。

## 四、对讲透文档的观察（仅供参考，本轮未改动 atoms/）

1. **淡收的“用过头”两条反例这轮起作用了**：它们正好管住了 C 稿踩的坑。建议保留，可以再补一条“别所有结尾都用叹气或呼气”，避免读者把“叹气”理解成唯一的收法。
2. **冷笔白描讲透全文没有带来净收益**：一句话定义就够用，B 稿还偏向写短写薄。可以考虑在“用过头”里加一个反例，提醒克制不等于删细节，结尾前需要有足够的物件铺垫。
3. **小处切入**：B 稿的手法分是满分 5.0，但 q01 的两位评分者都更喜欢 C 稿（C 让书签“往后挪了五页”，B 让书签停在原处）。这个差别是情节选择造成的，不是手法用得好坏。

## 五、局限（如实写明）

1. **样本小。** 9 题、18 次排序，同一题的两位评分者高度相关（8/9 题排序完全一致），有效样本更接近 9。B 对 C 的区间为 43.7%–83.7%，要分清“多出约 17 个百分点”还是“没有差别”，至少需要扩大几倍样本。
2. **写作者、评分者、判定者都是同一类模型**（Codex 子代理），彼此独立、不共享上下文，但审美偏好可能一致。**没有人类评分者。**
3. **手法判定者只有 1 位**，没有一致性数据。第一次调用时 q05、q06 的稿件在传输中被截断，判定者如实留空；这两题由另一位独立判定者补评（judge.csv 里标了“补评”）。所以 q05、q06 的手法分和其他 7 题出自不同的人。
4. **子代理不能读文件。** 第一批 7 个子代理按“读取 prompts/*.md”的指令执行时，全部被沙箱拦下，没有产出稿件，这批作废。之后改由协调者把 prompts/*.md 的全文逐字贴进子代理的指令，稿件和评分也由协调者把子代理的回复原样落盘。B 组讲透全文的逐字性由 `pilot.py prompts` 做了断言校验，贴入时没有改字，但这一步无法自动校验。
5. **抽签改过一次。** 第一次按固定种子 shuffle 时，A 有 7/9 次落在 Z 位，存在位置偏差风险。所以在任何评分开始之前，改成了拉丁方轮转：每个条件在 X、Y、Z 三个位置上各出现 3 次。旧的 key 已被覆盖，没有用于任何评分。
6. **原稿仍是刻意写坏的**，比真实稿子更好改。这里测的是“教会模型改稿”，不是“教会人写作”。
7. **通用指令比第一轮多了一句“保留文末的（综合创作）”**，三组相同，不影响组间对比。
8. **本轮没有跑 AI 味检测器。** 第一轮已经证明它在两三百字的短文本上几乎全是 0 分、没有区分力，所以本轮的 AI 腔一项只用评分者的打分。
9. **偏好评分者能看到原稿**，可能因为某篇“离原稿太近”而扣分。q03、q07 的 A 稿都被点评为“基本是原稿润色”。这对三组一视同仁，但会放大 A 与 B、C 之间的差距。

## 六、文件

- tasks.json：9 道新题（与第一轮题材不重复）、原稿、通用指令、种子
- prompts/：27 份写作提示，`qNN--{A,B,C}.md`，B 段从讲透原文逐字切出
- runs/：27 篇改写稿，`qNN--{A,B,C}.md`
- key.json、assign.json：抽签结果（拉丁方轮转）和评分者分配（每题 2 人，R1–R3 轮转）
- blind/、judge/：评分者和判定者看到的匿名包，只有 X/Y/Z，不含条件，泄露扫描 0 处
- ratings_R1.csv、ratings_R2.csv、ratings_R3.csv、ratings.csv：18 条偏好评分，含分项分和理由
- judge.csv：27 篇的手法分
- results.json、results.md：脚本解盲汇总；checks.json：照抄示范与流水账检查
- pilot.py：`prompts`、`blind`、`score`、`checks` 四个子命令，复用 eval/score.py 的 wilson()
