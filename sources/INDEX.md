# 语料出处索引

> 本仓库**不收录任何第三方文章的全文**。
> 这里只记录：① 蒸馏用了哪 21 篇；② 每篇的技法贡献；③ 本地怎么自备语料。
>
> 原因：那 21 篇是《人物》《三联生活实验室》的受版权保护作品，全文镜像既越界，
> 也让本仓库的 CC 许可无法覆盖它们。技法表本身是转换性使用的产物，才是真资产。

## 一、为什么删全文

删掉约 600KB 全文之后，仓库没有变弱，反而变清楚了三件事：

1. **许可边界干净了。** LICENSE 只管本仓库原创的技法与文档，不再有「授权写一半、
   侵权写一半」的灰区。
2. **技法库更可信了。** 读者看的是「从 11 篇里提炼出 21 条原子」，而不是
   「这里躺着 11 篇别人的文章」。前者是研究，后者是搬运。
3. **有争议的素材彻底出库。** 其中一篇（MU5735）原发已删除。明知已删仍镜像，
   性质从「合理引用」变成「二次传播」，这一条必须删干净——技法价值完全可以用
   抽象描述保留（见 feature-writing 的 A7「群像切片」），不需要原文。

## 三、例证引用规范（全库统一）

各引擎的原子表里保留的短引文，一律遵守三条：

1. **单个引文 ≤ 50 字**，只取支撑该技法所需的最小片段。
2. **逐条标注来源**：篇名 + 媒体 + 年份（例如「《脸基尼》三联 2026」）。
3. **不复现段落结构**：引文只用于证明「存在这种写法」，不用于替代阅读原文。

超过 50 字的引文、成段的场景、完整的人物对话——一律不收。

## 四、本地语料（自备，不入库）

要在本地跑完整体检（checker 回归、eval 盲评），需要语料原文。做法：

```bash
# 仓库已 gitignore 这些路径，放进去不会被提交
mkdir -p feature-writing/references/sources/local
mkdir -p human-voice-writing/references/sources/local

# 按 INDEX 的篇名自行取得 10 篇 + 11 篇，命名规范：
#   媒体-YYYY-MM-DD-标题.txt
# 例如：
#   人物-2020-09-08-外卖骑手，困在系统里.txt
```

放进之后：

```bash
python tools/ai_flavor_checker.py --engine human-voice-writing \
  human-voice-writing/references/sources/local/*.txt
```

预期：11 篇三联全部 < 30 分。这是 checker 的**最重要的校准断言**——
如果原文都过不了自己的门槛，说明门槛定错了，不是文章有问题。
